# Lakshmi Landing — рабочие инструкции

## Оркестрация задач (обязательно для объёмных задач)

Когда пользователь даёт объёмную задачу (несколько файлов, несколько разделов, несколько компонентов), ВСЕГДА применяй следующую схему:

### Схема оркестрации

1. **Анализ задачи** — перед запуском определи:
   - Можно ли декомпозировать на независимые части?
   - Сколько агентов нужно (1 агент = 1 независимый модуль работы)
   - Какие части конкурентны (разные файлы) — запускай параллельно
   - Какие части зависимы (нужен результат предыдущего) — запускай последовательно

2. **Дивергенция (для сложных/субъективных задач)** — для задач где важно качество решения (дизайн раздела, текст, структура), запускай **2 агента** на одну и ту же задачу с разными инструкциями/подходами. Затем ты сам выбираешь лучший вариант или объединяешь лучшее из обоих.

3. **Параллельный запуск** — все независимые агенты запускаются в одном сообщении (run_in_background: true), не по одному.

4. **Верификация** — после завершения всех агентов проверяй результат: нет ли конфликтов, соответствует ли задаче, нет ли пропущенных частей.

5. **Коммит только после проверки** — git add/commit/push выполняется один раз после того, как все агенты завершили работу и результат проверен.

### Примеры декомпозиции

- "Обнови все 9 страниц" → 9 агентов параллельно
- "Разработай дизайн новой секции" → 2 агента с разными концепциями → выбор лучшего
- "Добавь галерею и обнови стили" → агент 1: CSS, агент 2-10: HTML-страницы параллельно
- "Проверь и исправь все ошибки" → агент-аудитор → N агентов-исправщиков параллельно

### Шаблон отчёта пользователю

После завершения всех агентов давай краткий отчёт:
- Сколько агентов запущено и по какой задаче
- Что сделано в каждом направлении
- Что выбрано при дивергенции и почему
